# 可玩性与趣味性优化方案

针对 Ball And Wall 现状（50 关线性流程、一套 bonus 掉落、无进度评价、无社交、
刚接入的金币与道具系统）给出的下一步方案。每项都标注了落点文件与代价，按
「投入产出比」排序，不是许愿单。

判断标准始终是同一个：**这一项能不能提高玩家再玩一局的概率**。变现只是这个
指标的副产品——留不住人的游戏，商店做得再好也只是在向同一批人反复推销。

---

## P0 · 手感（juice）

投入最小、体感提升最大的一档。街机打砖块的乐趣有相当比例来自「砸中的一瞬间
发生了多少事」，而目前砸中一块砖只有一个音效和一次贴图切换。

| 项 | 做法 | 落点 |
| --- | --- | --- |
| 命中顿帧 | 击碎砖块时暂停 2–3 帧再继续，比任何粒子都更能强化打击感 | `entity/ball.js` 的碰撞分支 + `createjs.Ticker` |
| 连击 | 不落板连续击碎的计数，分数倍率 ×1.1/×1.2…，音效音高随连击上升 | 复用 `dashboard/score.js`，音高用 SoundJS 的 `playbackResource` |
| 命中屏震 | 已有 `stage.earthquake()`，目前只用于 die/earthquake bonus；按砖块硬度给一次极短的 2px 震动 | `stage.js` 已具备，只需调用 |
| 挡板挤压 | 接球瞬间挡板纵向压缩 15% 再弹回（80ms） | `entity/paddle.js`，`createjs.Tween` 已在用 |
| 碎块粒子 | `entity/particle.js` 已存在，扩大到每次击碎都喷 4–6 片 | `entity/particle.js` |
| 差点漏球 | 球擦着挡板边缘接住时短暂高亮，玩家会记住这一下 | `entity/paddle.js` |

**代价**：合计 1–2 天，无新美术资源，无架构改动。

**风险**：顿帧会影响 `event.delta` 驱动的物理积分，必须在 `Ticker` 层面
挂起而不是跳过一次 `update()`，否则球会瞬移。这一点在实现前先补一条单元
测试（`tests/unit/` 已经覆盖球的速度逻辑，扩起来很便宜）。

## P0 · 关卡目标与三星评价

现在通关只有「过 / 没过」两种状态，`round-win` 窗口已经在收集 time / lives /
score 三个维度，却没有把它们变成目标。

- 每关三星：时间星、不掉命星、分数星。存进 `window-rounds` 的 `data`（结构
  已有，目前只存解锁状态）。
- 星数作为下一章节的解锁条件，给玩家重玩老关的理由——这是线性关卡游戏留存
  的主要来源。
- 星数同时是金币产出的乘数，把「玩得好」和「买得起」接上（`shop/rewards.js`
  已经按 score/lives 结算，加一个星数系数即可）。
- 关卡目标多样化：限时清关、限定弹跳次数、指定砖块优先、不使用道具通关。
  关卡串格式 `<name>:<x>,<y>,<type>;…` 可以在 name 段后追加目标标记，
  `levels.js` 解析处扩展一个字段即可，不破坏既有关卡串。

**代价**：3–5 天。**收益**：把 50 关的一次性内容变成可重复内容。

## P1 · 难度曲线与新手保护

`entity/ball.js` 里球速每次撞墙 `increaseSpeed()`，上限 `maxSpeed = 6.5 × pixelRatio`。
这是一条只升不降的曲线，对新手过陡、对老手后期又过平。

- 每关设定目标速度区间，超出后不再累加，进入下一关重置。
- 前三关开启「新手保护」：球落底一次不扣命（每关一次），并在界面上明确
  提示这是保护而不是 bug。首次流失几乎都发生在前三关。
- 自适应：连续两次在同一关失败，下一次开局挡板略宽——不要告诉玩家，也
  不要在有排行榜的模式里启用。
- 后期难度靠**新机制**而不是靠加速：移动砖块、需要连击才能破的砖、
  会补位的砖。`entity/block/` 已经有注册表机制（`entity/block/_registry.js`），
  加一种交互砖是加一个条目。

## P1 · 会话结构与回访理由

- **续关**：game over 后花金币原地续命，是打砖块品类最自然的金币消耗点，
  也是唯一一个玩家真心愿意付费的时刻。价格随本局续关次数递增。
- **每日挑战**：用固定种子生成一关，全服同一关，只能打一次，排行榜结算。
  关卡编辑器（`levels-editor.js`）已经能生成关卡串，种子化生成是小改动。
- **每日登录奖励**：递增金币，第 7 天给一个道具。成本极低，回访效果确定。
- **离线/PWA**：整个游戏是纯静态资源，加一个 service worker 就能离线可玩并
  支持「添加到主屏幕」。对移动端留存的作用远大于它的实现成本。

## P1 · 移动端体验（延续本次修复）

本次已经修掉弹窗超出可视区域的问题（`window/_base.js::_fit()`）。同一类问题
还剩几处：

- **安全区**：刘海屏横屏时左右各有一条不可点区域。`#a-hud-toggle` 和
  `#a-item-bar` 都固定在屏幕边缘，应该加 `env(safe-area-inset-left/right)`，
  并在 viewport meta 上加 `viewport-fit=cover`。
- **暂停键**：目前只能通过打开仪表盘面板间接暂停。一个显式的暂停按钮是
  移动端的基本预期。
- **触感反馈**：`navigator.vibrate(10)` 用在击碎砖块和道具生效上，安卓端
  提升明显（iOS Safari 不支持，需优雅降级）。
- **断点样式表**：`css/mobile.css`、`css/ie.css` 已经是孤儿文件，其余断点
  样式表只对弹窗与按钮生效（场地已改为统一缩放）。趁这次弹窗改成缩放适配，
  可以把断点样式表里关于 `.lbx-*` 尺寸的部分大幅削减——现在它们互相打架，
  是本次这个 bug 的根因。

## P2 · 社交与内容

- **排行榜**：`round-win` 已有 score/time/lives，缺的只是一个后端。按关卡
  排名比按总分排名更有效——玩家更愿意去打一个自己差 2 秒的榜。
- **成绩卡分享**：`core/helper/share.js` 已存在。生成一张带关卡缩略图和成绩
  的图片比分享一条链接的转化高一个量级。
- **UGC**：关卡编辑器已经能产出关卡串并存进 `core.storageGlobal`。补一个
  「发布 / 订阅关卡」的后端，就有了持续内容供给。这是这个项目里最被低估的
  已有资产。

## P2 · 变现设计（在已接入的基础上）

已经实现的部分：金币（游玩产出 + 充值获得）、7 种道具、商店双页签、
支付网关抽象。下一步建议，按「不伤害游戏」的顺序：

1. **外观类**：挡板皮肤、球的拖尾颜色、粒子配色。纯外观、不影响平衡，是
   长期收入最健康的部分，而且这套渲染已经支持换贴图。
2. **首充奖励 / 新手礼包**：一次性、低价、高价值感，是转化率最高的单品。
3. **续关**（见上）：真实付费意愿最强的时刻。
4. **广告**：如果要接，只接激励视频（看广告换一次续关或一个道具），
   不接插屏。插屏广告在这个品类的留存损失大于收入。

必须坚持的红线：

- **不做付费墙**。商店里每一件道具的效果都必须是免费玩家能通过掉落拿到的
  ——这是当前 `shop/powerups.js` 的设计前提，写在了 CLAUDE.md 里。
- **服务端结算**。`wallet.js` 现在是客户端缓存，玩家可以直接改
  localStorage。在真实支付接入之前这没有代价，接入之后必须由服务端持有
  余额（`wallet.setServerState()` 就是为此预留的）。
- **合规**：面向中国大陆发行需要处理未成年人消费限制、实名与消费提示，
  以及应用商店的支付渠道要求。这一项会影响支付 provider 的选型，建议在
  拿到第三方支付文档时一并确认。

## P2 · 数据埋点

上面每一条都需要验证，而现在游戏没有任何埋点。最小可用集合：

`round_start` / `round_clear` / `round_fail`（带关卡号、时长、剩余命）、
`shop_open` / `item_buy` / `topup_start` / `topup_result`、
`session_start` / `session_end`。

`core/mediator` 已经在广播 `game:game-start`、`game:stage-clear`、
`game:level-start`，新增的 `shop:item-used` 也走同一条总线——加一个订阅所有
这些事件的 `analytics.js` 即可，不需要在业务代码里插桩。

**这一项应该先于 P0 之后的任何一项做**：没有埋点，关卡难度曲线只能靠猜。

---

## 建议的执行顺序

1. 手感（P0）+ 埋点 —— 一周内可见效果，且为后面所有决策提供依据
2. 三星评价与关卡目标（P0）
3. 续关 + 每日挑战 + 每日奖励（P1）
4. 移动端安全区、暂停键、PWA（P1）
5. 排行榜与成绩卡分享（P2）
6. 外观类商品与首充（P2）
